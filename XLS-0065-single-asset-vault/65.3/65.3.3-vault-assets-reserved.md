# 65.3.3 Vault Assets Reserved

## 1. Abstract

Under `LendingProtocolV1_2`, the `Vault` ledger entry gains an `AssetsReserved` field. It records the part of `Vault.AssetsTotal` that is set aside for pending Loans created by the two-step loan flow in [XLS-66.3.1](../../XLS-0066-lending-protocol/66.3/66.3.1-two-step-loan-creation.md). Reserved assets stay in the Vault _pseudo-account_ but are not part of `Vault.AssetsAvailable`, so they cannot be withdrawn or lent again. The `vault_info` RPC returns the new field.

## 2. Motivation

In the two-step loan flow, the Loan Broker proposes a Loan and the Borrower accepts it later. Between the two steps the principal must stay in the Vault, because the Borrower has not accepted the Loan yet. It must also be unavailable to depositors and to other Loans, or the Borrower could accept a Loan that the Vault can no longer fund.

`Vault.AssetsAvailable` cannot express this alone. If the principal is only removed from `AssetsAvailable`, the Vault _pseudo-account_ balance no longer matches any Vault field, and an observer cannot tell lent assets from assets held for pending Loans. `AssetsReserved` makes the held amount explicit.

## 3. Specification

This patch changes the parent [XLS-65](../README.md) sections named below. All other parent behavior is unchanged.

### 3.1 Ledger Entry: `Vault`

#### 3.1.1 Fields

Add this field to parent [§3.1.2](../README.md#312-fields):

| Field Name       | Constant | Required | JSON Type | Internal Type | Default Value | Description                                                                      |
| ---------------- | :------: | :------: | :-------: | :-----------: | :-----------: | -------------------------------------------------------------------------------- |
| `AssetsReserved` |    No    |   Yes    | `number`  |   `NUMBER`    |      `0`      | The amount of Vault assets reserved for pending Loans that are not yet accepted. |

`AssetsReserved` is part of `AssetsTotal` and is not part of `AssetsAvailable`. The assets are still held by the Vault _pseudo-account_. As with `LossUnrealized`, the default value is `0`.

Only these transactions change `AssetsReserved`, as specified in [XLS-66.3.1](../../XLS-0066-lending-protocol/66.3/66.3.1-two-step-loan-creation.md):

- `LoanSet` that proposes a Loan increases it by the Loan principal.
- `LoanAccept` decreases it by the Loan principal when the principal is sent to the Borrower.
- `LoanDelete` of a pending Loan decreases it by the Loan principal and returns that amount to `AssetsAvailable`.

#### 3.1.2 Invariants

When the amendment is enabled, amend parent [§3.1.10](../README.md#3110-invariants) as follows.

Parent invariant 9 also requires `Vault.AssetsReserved` to be zero on creation. Parent invariant 10 also requires the deleted Vault to have `AssetsReserved == 0`.

Parent invariant 5, including its `fixCleanup3_4_0` form from [XLS-65.2](../65.2/README.md), uses `Vault.AssetsTotal - Vault.AssetsAvailable - Vault.AssetsReserved` in place of `Vault.AssetsTotal - Vault.AssetsAvailable`. `Vault.LossUnrealized` is therefore bounded by the assets lent out by active Loans, not by assets reserved for pending Loans. The one-unit `IOU` slack is unchanged.

In parent invariant 16, add `LoanAccept` with `MustModifyVault` and `LoanDelete` with `MayModifyVault` to the list of transaction types that may modify a `Vault`. `LoanDelete` modifies the Vault only when it deletes a pending Loan.

Append these invariants:

18. `Vault.AssetsReserved >= 0`.
19. `Vault.AssetsAvailable + Vault.AssetsReserved <= Vault.AssetsTotal`.
20. `Vault.AssetsReserved` may only be changed by `LoanSet`, `LoanAccept` and `LoanDelete`. Every other transaction that modifies the entry must leave it unchanged.

When the amendment is not enabled, `AssetsReserved` is absent and these changes do not apply.

### 3.2 Unchanged Transactions

`VaultWithdraw` and `VaultClawback` are unchanged. They are already limited by `Vault.AssetsAvailable`, so reserved assets cannot be withdrawn or clawed back while a Loan is pending. `VaultDelete` is unchanged: it requires `AssetsTotal == 0`, which by invariant 19 also requires `AssetsReserved == 0`.

### 3.3 RPC: `vault_info`

#### 3.3.1 Response Fields

Add this field to parent [§3.9.2](../README.md#392-response-fields):

| Field Name             | Always Present? | JSON Type | Description                                                                  |
| ---------------------- | :-------------: | :-------: | ---------------------------------------------------------------------------- |
| `vault.AssetsReserved` |       No        | `string`  | Amount of assets reserved for pending Loans that have not yet been accepted. |

The field is absent when the amendment is not enabled.

## 4. Rationale

Keeping reserved assets inside `AssetsTotal` means that, in a cash-basis Vault ([XLS-65.1.3](../65.1/65.1.3-vault-cash-basis.md)), a pending Loan does not change the value of Vault shares on its own. In an accrual-basis Vault the proposal also books the expected interest into `AssetsTotal`; see [XLS-66.3.1](../../XLS-0066-lending-protocol/66.3/66.3.1-two-step-loan-creation.md) §7. Taking them out of `AssetsAvailable` stops a depositor from withdrawing them and stops a second Loan from using them. Excluding reserved assets from the `LossUnrealized` bound in invariant 5 keeps an unrealized loss from discounting assets that are still in the Vault. A separate field, rather than a sum over pending Loans, lets invariants and RPC clients read the reserved amount from the Vault alone.

## 5. Test Plan

The reference implementation tests that `AssetsReserved` is zero on a new Vault, increases when a Loan is proposed, decreases when it is accepted or deleted, and stays unchanged for every other Vault and Lending transaction. It tests that `VaultWithdraw` cannot withdraw reserved assets, checks invariants 18-20 after each of these transactions, and checks that `vault_info` returns the field. It runs the same tests with the amendment disabled and confirms that the field is absent.

## 6. Security Considerations

Reserved assets are held by the Vault _pseudo-account_ but are committed to a pending Loan. If `AssetsReserved` were not checked, a Borrower could accept a Loan after the principal had been withdrawn or lent to someone else. Invariant 19 rules that out. A pending Loan can hold Vault liquidity until it is accepted or deleted; [XLS-66.3.1](../../XLS-0066-lending-protocol/66.3/66.3.1-two-step-loan-creation.md) describes how a pending Loan is removed.
