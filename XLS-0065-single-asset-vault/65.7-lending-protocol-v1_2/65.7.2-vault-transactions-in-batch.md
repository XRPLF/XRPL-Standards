# 65.7.2 Vault Transactions in Batch

## 1. Abstract

Under `LendingProtocolV1_2`, the Vault transactions `VaultCreate`, `VaultSet`, `VaultDelete`, `VaultDeposit`, `VaultWithdraw` and `VaultClawback` may be inner transactions of a [Batch](../../XLS-0056-batch/README.md). Before the amendment, a `Batch` containing any of them fails with `temINVALID_INNER_BATCH`.

## 2. Motivation

Vault operations are often one step of a larger sequence, for example creating a Vault and making the first deposit, or withdrawing and paying out in one atomic unit. `Batch` provides that atomicity for other transactions, but the Vault transactions were excluded from it.

## 3. Specification

### 3.1 Transaction: `Batch`

#### 3.1.1 Fields

No fields are added or removed.

#### 3.1.2 Failure Conditions

##### 3.1.2.1 Data Verification

This changes the inner-transaction checks of [XLS-56](../../XLS-0056-batch/README.md):

- Before `LendingProtocolV1_2`: an inner transaction of type `VaultCreate`, `VaultSet`, `VaultDelete`, `VaultDeposit`, `VaultWithdraw` or `VaultClawback` fails the `Batch` with `temINVALID_INNER_BATCH`.
- `LendingProtocolV1_2`: the check does not apply. These inner transactions go through the same Batch checks as any other inner transaction, including their own preflight.

The same amendment and the same check also cover the Lending Protocol transactions (`LoanBrokerSet`, `LoanBrokerDelete`, `LoanBrokerCoverDeposit`, `LoanBrokerCoverWithdraw`, `LoanBrokerCoverClawback`, `LoanSet`, `LoanDelete`, `LoanManage` and `LoanPay`). Their deltas belong to [XLS-66.7](../../XLS-0066-lending-protocol/66.7-lending-protocol-v1_2/README.md).

#### 3.1.3 State Changes

Unchanged. Each Vault inner transaction applies as specified in [XLS-65](../README.md) and its patches.

## 4. Rationale

The restriction was a blanket exclusion of the new Vault and Lending transactions from `Batch`. Lifting it under the same amendment as the other Lending changes lets the two features be combined without a separate amendment.

## 5. Security Considerations

An inner Vault transaction is checked and applied exactly as if it were submitted on its own. The `Batch` adds atomicity across inner transactions but grants no extra permission. In particular, an inner `VaultWithdraw` or `VaultClawback` still needs its own authorization and still passes the Vault invariants.
