# 66.3.4 Loan Data

## 1. Abstract

Under `LendingProtocolV1_2`, `LoanSet` writes its `Data` field to a new optional `Data` field on the `Loan` ledger entry it creates. Before the amendment, `LoanSet` accepts and length-checks `Data` but stores it on no ledger entry.

## 2. Motivation

The parent specification defines `Data` on `LoanSet` ([§3.8.1](../README.md#381-fields)) and rejects a value over 256 bytes ([§3.8.5.1](../README.md#3851-data-verification), check 5). The `Loan` ledger entry ([§3.2.2](../README.md#322-fields)) has no `Data` field, and the `LoanSet` state changes ([§3.8.6](../README.md#386-state-changes)) do not mention it, so the value exists only in the transaction. A `LoanBroker` stores the `Data` of its `LoanBrokerSet` ([§3.1.2](../README.md#312-fields)); a `Loan` has no equivalent. Reading the metadata of a `Loan` means finding the `LoanSet` that created it in transaction history; a `ledger_entry` request for the `Loan` does not return it.

## 3. Specification

This patch changes the parent [XLS-66](../README.md) sections named below. All other parent behavior is unchanged.

### 3.1 Ledger Entry: `Loan`

#### 3.1.1 Fields

Append to parent [§3.2.2](../README.md#322-fields):

| Field Name | Constant | Required | JSON Type | Internal Type | Default Value | Description                                                                                    |
| ---------- | :------: | :------: | :-------: | :-----------: | :-----------: | :--------------------------------------------------------------------------------------------- |
| `Data`     |   Yes    |    No    | `string`  |    `BLOB`     |     None      | Arbitrary metadata about the `Loan`, from the `LoanSet` that created it. Limited to 256 bytes. |

`Data` is set when the `Loan` is created. No transaction changes it afterwards.

### 3.2 Transaction: `LoanSet`

#### 3.2.1 Fields

Unchanged. `Data` keeps its parent definition.

#### 3.2.2 Failure Conditions

Unchanged. Parent [§3.8.5.1](../README.md#3851-data-verification) check 5 still rejects a `Data` over 256 bytes with `temINVALID`.

#### 3.2.3 State Changes

Amend parent [§3.8.6](../README.md#386-state-changes) step 1, "Create the `Loan` object":

- `LendingProtocol (parent)`: `Data` is not stored.
- `LendingProtocolV1_2`: if `Data` is present and non-empty, set `Loan.Data` to it. An absent or empty `Data` leaves `Loan.Data` absent.

#### 3.2.4 Example JSON

A `Loan` created under `LendingProtocolV1_2` by a `LoanSet` carrying `"Data": "48656C6C6F"` includes:

```json
{
  "LedgerEntryType": "Loan",
  "Data": "48656C6C6F"
}
```

The other fields are as in the parent specification.

## 4. Rationale

`LoanSet` already carries `Data`, and both parties sign it: the Borrower or Lender submitting it, and the other through `CounterpartySignature`, which `LoanSet` verifies over the same transaction. Storing it gives a `Loan` the same on-ledger metadata a `LoanBroker` has, readable with `ledger_entry`, and a place for an off-ledger reference such as the hash or URI of a loan agreement next to the terms it describes.

The alternative was to remove `Data` from `LoanSet`. That rejects transactions clients already send and leaves a `Loan` with no metadata field.

`Data` is constant because no Lending Protocol transaction rewrites the terms of a `Loan` after creation.

## 5. Backwards Compatibility

Before `LendingProtocolV1_2`, the parent behavior applies unchanged. After the amendment, a `LoanSet` that succeeded before still succeeds, and its `Loan` also holds `Data`. A `Loan` created before the amendment has no `Data`, and nothing adds it later.

## 6. Security Considerations

`Loan.Data` is bounded by the existing 256-byte check, the same bound as `LoanBroker.Data`. No transaction reads `Loan.Data`. The Borrower and the Lender both sign the `LoanSet`, one as its submitter and the other through `CounterpartySignature`, so neither can attach `Data` the other did not sign.

## 7. Test Plan

Tests run `LoanSet` with `LendingProtocolV1_2` enabled and disabled for these cases:

- `Data` of 5 bytes, and of 256 bytes: stored on the `Loan` when enabled, absent when disabled.
- `Data` empty, and `Data` absent: `Loan.Data` absent in both states.
