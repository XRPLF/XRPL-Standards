# 66.3.3 Private LoanBroker

## 1. Abstract

Under `LendingProtocolV1_2`, a `LoanBroker` can be created as private. A private `LoanBroker` references a [Permissioned Domain](../../XLS-0080-permissioned-domains/README.md) through `DomainID`, and `LoanSet` succeeds only if the Borrower is a member of that domain: the domain owner, or an account holding a valid accepted [Credential](../../XLS-0070-credentials/README.md) listed in the domain's `AcceptedCredentials`. Public LoanBrokers are unchanged.

## 2. Motivation

A Loan Issuer may need every Borrower to meet legal obligations, such as KYC. Permissioned Domains already express "which accounts may participate" in terms of on-ledger credentials. Attaching a domain to a `LoanBroker` lets the ledger enforce that rule at Loan origination instead of relying only on off-chain checks.

## 3. Specification

This patch changes the parent [XLS-66](../README.md) sections named below. All other parent behavior is unchanged.

### 3.1 Ledger Entry: `LoanBroker`

#### 3.1.1 Fields

Add this field to parent [§3.1.2](../README.md#312-fields):

| Field Name | Constant | Required | JSON Type | Internal Type | Default Value | Description                                                          |
| ---------- | :------: | :------: | :-------: | :-----------: | :-----------: | -------------------------------------------------------------------- |
| `DomainID` |    No    |    No    | `string`  |   `HASH256`   |     None      | The `PermissionedDomain` object ID associated with the `LoanBroker`. |

`DomainID` is present only on a private `LoanBroker`. When present, it is non-zero.

#### 3.1.2 Flags

The parent `LoanBroker` defines no flags. Under `LendingProtocolV1_2`, it supports:

| Flag Name              |  Flag Value  | Modifiable? | Description                                         |
| ---------------------- | :----------: | :---------: | --------------------------------------------------- |
| `lsfLoanBrokerPrivate` | `0x00010000` |    `No`     | If set, indicates that the `LoanBroker` is private. |

#### 3.1.3 Access Control

A `LoanBroker` is private if `lsfLoanBrokerPrivate` is set, and public otherwise. The flag can be set only when the `LoanBroker` is created, using the `tfLoanBrokerPrivate` flag on `LoanBrokerSet`. It cannot be set or cleared later. Any account may take out a Loan from a public `LoanBroker`.

A Borrower may take out a Loan from a private `LoanBroker` only if it is a member of the Permissioned Domain referenced by `LoanBroker.DomainID`. Following [XLS-80](../../XLS-0080-permissioned-domains/README.md), an account is a member if it is the domain owner, or if it holds an accepted, unexpired credential matching one entry in the domain's `AcceptedCredentials`.

The `LoanBroker.Owner` does not need to be a domain member to issue a Loan. If the Owner takes out a Loan from its own private `LoanBroker`, it is the Borrower and must be a domain member.

The domain does not change the signature requirements for `LoanSet`. Both the `LoanBroker.Owner` and the Borrower must still sign, so domain membership never authorizes a Loan on its own.

The `LoanBroker.Owner` can change or clear `DomainID`. While a private `LoanBroker` has no `DomainID`, no Loan can be issued from it.

Membership is checked against the current ledger state when `LoanSet` is applied. If the Borrower's credential is later revoked or expires, the domain's `AcceptedCredentials` change, the domain is deleted, or `DomainID` is changed or cleared, existing Loans are unaffected. `LoanPay`, `LoanManage`, and `LoanDelete` apply no domain check.

#### 3.1.4 Invariants

Replace the parent [§3.1.8](../README.md#318-invariants) placeholder with these invariants under `LendingProtocolV1_2`:

1. If a `LoanBroker` is modified (neither created nor deleted), `LoanBroker.Flags` is unchanged. In particular, `lsfLoanBrokerPrivate` is neither set nor cleared after creation.
2. If `LoanBroker.DomainID` is present, `lsfLoanBrokerPrivate` is set.
3. If `LoanBroker.DomainID` is present, it is non-zero.

### 3.2 Transaction: `LoanBrokerSet`

#### 3.2.1 Fields

Add this field to parent [§3.3.1](../README.md#331-fields):

| Field Name | Required | JSON Type | Internal Type | Default Value | Description                                                                                                                      |
| ---------- | :------: | :-------: | :-----------: | :-----------: | :------------------------------------------------------------------------------------------------------------------------------- |
| `DomainID` |    No    | `string`  |   `HASH256`   |     None      | The `PermissionedDomain` object ID to associate with the `LoanBroker`. On modification, an all-zero value clears the `DomainID`. |

#### 3.2.2 Flags

The parent `LoanBrokerSet` defines no transaction flags. Under `LendingProtocolV1_2`, it supports:

| Flag Name             |  Flag Value  | Description                                                                                  |
| --------------------- | :----------: | :------------------------------------------------------------------------------------------- |
| `tfLoanBrokerPrivate` | `0x00010000` | Indicates that the `LoanBroker` is private. It can only be set during `LoanBroker` creation. |

Without `LendingProtocolV1_2`, `LoanBrokerSet` accepts only the universal transaction flags, and a transaction with `tfLoanBrokerPrivate` fails with `temINVALID_FLAG`.

#### 3.2.3 Failure Conditions

Append these checks to parent [§3.3.3.1](../README.md#3331-data-verification), after checks 10 and 11 added by [XLS-66.3.2](./66.3.2-conditional-vault-id.md):

12. - `LendingProtocol (parent)`: The check does not apply.
    - `LendingProtocolV1_2`: The amendment is not enabled and `DomainID` is present. (`temDISABLED`)
13. - `LendingProtocol (parent)`: The check does not apply.
    - `LendingProtocolV1_2`: `LoanBrokerID` is not specified (creating new), and `DomainID` is present and zero. (`temMALFORMED`)
14. - `LendingProtocol (parent)`: The check does not apply.
    - `LendingProtocolV1_2`: `LoanBrokerID` is not specified (creating new), `DomainID` is present, and `tfLoanBrokerPrivate` is not set. (`temINVALID`)
15. - `LendingProtocol (parent)`: The check does not apply.
    - `LendingProtocolV1_2`: `LoanBrokerID` is specified (modifying existing) and `tfLoanBrokerPrivate` is set. (`temINVALID`)

Append these checks to parent [§3.3.3.2](../README.md#3332-protocol-level-failures):

12. - `LendingProtocol (parent)`: The check does not apply.
    - `LendingProtocolV1_2`: `DomainID` is present and non-zero, and no `PermissionedDomain` object with that ID exists. Applies to both creation and modification. (`tecOBJECT_NOT_FOUND`)
13. - `LendingProtocol (parent)`: The check does not apply.
    - `LendingProtocolV1_2`: `LoanBrokerID` is specified (modifying existing), `DomainID` is present (including zero), and `LoanBroker(LoanBrokerID)` does not have `lsfLoanBrokerPrivate` set. (`tecNO_PERMISSION`)

#### 3.2.4 State Changes

Under `LendingProtocolV1_2`, append these steps to parent [§3.3.4](../README.md#334-state-changes).

**If `LoanBrokerID` is not specified (creating new):**

8. If `tfLoanBrokerPrivate` is set:
   - Set `lsfLoanBrokerPrivate` on the new `LoanBroker`.
   - If `DomainID` is present, set `LoanBroker.DomainID = DomainID`.

**If `LoanBrokerID` is specified (modifying existing):**

9. If `DomainID` is present and non-zero, set `LoanBroker.DomainID = DomainID`.
10. If `DomainID` is present and zero, remove `LoanBroker.DomainID`.

#### 3.2.5 Invariants

Under `LendingProtocolV1_2`, `LoanBrokerSet` preserves the `LoanBroker` invariants in §3.1.4. A private `LoanBroker` is only created by a transaction with `tfLoanBrokerPrivate`, and a public `LoanBroker` never gains a `DomainID`.

### 3.3 Transaction: `LoanSet`

#### 3.3.1 Failure Conditions

Append these checks to parent [§3.8.5.2](../README.md#3852-protocol-level-failures). Each applies only when `LoanBroker.lsfLoanBrokerPrivate` is set. In checks 30 and 31, a matching credential is a `Credential` whose `Subject` is the Borrower and whose `Issuer` and `CredentialType` match an entry in the domain's `AcceptedCredentials`.

28. - `LendingProtocol (parent)`: The check does not apply.
    - `LendingProtocolV1_2`: `LoanBroker.DomainID` is absent. (`tecNO_AUTH`)
29. - `LendingProtocol (parent)`: The check does not apply.
    - `LendingProtocolV1_2`: No `PermissionedDomain` object with ID `LoanBroker.DomainID` exists. (`tecOBJECT_NOT_FOUND`)
30. - `LendingProtocol (parent)`: The check does not apply.
    - `LendingProtocolV1_2`: The Borrower is not the domain owner, holds no accepted, unexpired matching credential, and holds no expired matching credential. (`tecNO_AUTH`)
31. - `LendingProtocol (parent)`: The check does not apply.
    - `LendingProtocolV1_2`: The Borrower is not the domain owner, holds no accepted, unexpired matching credential, and holds at least one expired matching credential. (`tecEXPIRED`)

The domain owner is a domain member without holding any credential, so checks 30 and 31 never fail for the domain owner.

#### 3.3.2 State Changes

If check 31 fails, the transaction deletes every expired matching credential of the Borrower, as other credential-checking transactions do under [XLS-70](../../XLS-0070-credentials/README.md). No other state changes are applied. The parent [§3.8.6](../README.md#386-state-changes) steps are otherwise unchanged.

#### 3.3.3 Invariants

Under `LendingProtocolV1_2`, no `LoanSet` against a private `LoanBroker` succeeds unless, at the time it is applied, the Borrower is a member of the existing Permissioned Domain referenced by `LoanBroker.DomainID`.

### 3.4 Unchanged Transactions

`LoanPay`, `LoanManage`, `LoanDelete`, `LoanBrokerDelete`, and the `LoanBrokerCover` transactions apply no domain or credential check and behave the same for private and public LoanBrokers.

## 4. Rationale

Making `lsfLoanBrokerPrivate` immutable means Vault depositors and Borrowers can rely on whether a `LoanBroker` applies access control. Keeping `DomainID` modifiable lets the Owner move to a new domain or credential issuer without recreating the `LoanBroker`. A private `LoanBroker` without a domain fails closed instead of becoming public.

Credentials are checked only at origination. Adding a credential check to repayment would let a revoked or expired credential block a Borrower from repaying, which harms the Vault depositors that the check is meant to protect.

The domain owner is treated as a member to match the [XLS-80](../../XLS-0080-permissioned-domains/README.md) membership rule used by other domain-gated features.

## 5. Backwards Compatibility

Existing `LoanBroker` objects have no flags and no `DomainID`, so they are public and unaffected. Before `LendingProtocolV1_2`, `LoanBrokerSet` rejects `DomainID` with `temDISABLED` and `tfLoanBrokerPrivate` with `temINVALID_FLAG`.

## 6. Test Plan

The reference implementation tests `LoanBrokerSet` with the amendment enabled and disabled: creation with and without `tfLoanBrokerPrivate`, with zero, non-zero, and nonexistent `DomainID`, and `DomainID` without `tfLoanBrokerPrivate`; modification that sets, changes, and clears `DomainID` on a private broker, sets `DomainID` on a public broker, and sets `tfLoanBrokerPrivate`. It tests `LoanSet` against a private broker with no `DomainID`, a deleted domain, a Borrower with no credential, an unaccepted credential, an expired credential (confirming deletion), a valid credential, and the domain owner as Borrower. It confirms that `LoanPay` succeeds after the Borrower's credential is deleted, the domain is deleted, or `DomainID` is cleared. Invariant tests confirm that changing `LoanBroker.Flags`, a `DomainID` on a public broker, and a zero `DomainID` are rejected.

## 7. Security Considerations

A private `LoanBroker` relies on the accepted credential issuers and on the owner of the referenced Permissioned Domain. The domain owner can change `AcceptedCredentials` or delete the domain, even when it is not the `LoanBroker.Owner`, and is itself always a domain member. Credential checks give point-in-time authorization for new Loans: revocation, expiration, or domain deletion does not unwind an outstanding Loan or add a check to repayment. LoanBroker Owners must account for this control and non-retroactive behavior when using credentials for compliance.
